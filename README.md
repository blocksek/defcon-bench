# defcon-bench

An eval harness for measuring how well LLM agents solve **Capture-The-Flag**
challenges, end to end. The first dataset is the **DEF CON CTF Qualifiers**
(open-source releases by the [Nautilus Institute](https://github.com/Nautilus-Institute)).

Each challenge is set up with its real infrastructure — Docker images, network
services — and a tool-calling agent is turned loose on it: it gets a shell, the
challenge files, and (for networked challenges) a live service to attack. The
harness grades whatever flag the agent recovers against a ground truth the agent
never sees.

```
challenge.yaml ──► build infra (docker) ──► agent loop (shell + submit_flag) ──► grade ──► report
```

## Why

CTF challenges are a clean substrate for measuring real agentic capability:
reverse engineering, exploitation, crypto, and web, with an unambiguous success
signal (the flag) and no partial-credit ambiguity. Unlike static Q&A, solving
requires *doing* — reading code, writing exploits, and interacting with a live
service.

## How it works

- **Challenge** (`challenges/<year>/<id>/challenge.yaml`): declares the category,
  the player-facing prompt, how the challenge is delivered (offline artifact or
  networked service), how to build it, and the ground-truth flag (kept out of
  everything the agent sees). See [`docs/AUTHORING.md`](docs/AUTHORING.md).
- **Runner** (`ctfbench/runner.py`): builds the challenge, brings up its service
  with `docker compose`, drops the artifacts into a sandbox, and runs the agent.
- **Agent** (`ctfbench/agent/`): a provider-agnostic tool-calling loop with two
  tools — `run_bash` (a shell in the sandbox) and `submit_flag`. The first
  backend is **OpenAI**; a `MockProvider` drives real solves in tests without an
  API key.
- **Sandbox** (`ctfbench/sandbox.py`): the agent's shell runs either inside a
  Docker container joined to the challenge's network (realistic) or as a local
  subprocess (`--no-docker`, handy for offline challenges and CI).
- **Grading** (`ctfbench/grading.py`): a solve is an exact-match flag submission
  (or the ground-truth flag observed verbatim in tool output). Format-shaped
  guesses never score.

## Quick start

```bash
pip install -e '.[openai]'

# list the dataset
ctfbench list

# inspect one challenge
ctfbench show 2023-omgzip

# run an agent (OpenAI) against a challenge; Docker sandbox + service infra
export OPENAI_API_KEY=sk-...
ctfbench run 2022-simple-service --model openai:gpt-4o --out runs/

# run every challenge, write JSON + Markdown reports
ctfbench run --model openai:gpt-4o --out runs/
```

Offline challenges can run without a Docker daemon:

```bash
ctfbench run 2023-omgzip --model openai:gpt-4o --no-docker
```

### The solver sandbox image

For the Docker sandbox, build an image with the tooling agents expect
(`python3`, `pwntools`, `gdb`, `binutils`, `nc`, …):

```bash
docker build -t ctfbench/solver:latest docker/solver
```

Point runs at a different image with `--solver-image`.

## Reproducibility & provenance

Every challenge records its `source` (upstream repo + path + license). Build
outputs (`dist/`, `build/`, `bin/`) are gitignored and regenerated by
`ctfbench build`. Ground-truth flags are ours (baked into each instance at
build time), so a solve is unambiguous for the instance under test.

## Dataset

12 challenges across DEF CON CTF Qualifiers 2022–2024 (pwn, web, reversing,
crypto, misc), each rebuilt from the Nautilus Institute open-source releases as
a self-contained harness challenge. Run `ctfbench list` to see them, or
`ctfbench validate` to lint the set.

- `2023-omgzip` (offline reversing) is verified end-to-end without Docker — a
  reference decoder recovers the flag and the mock agent solves it in the tests.
- `2022-simple-service` (networked service) has its flag flow verified locally.
- The 10 other service challenges are packaged with correct-by-construction
  infra + flag wiring and pass `ctfbench validate`; their Docker builds have not
  been live-verified in a Docker-less environment.
- Per-challenge verification state, caveats, and each challenge's write-up
  reference: [`challenges/STATUS.md`](challenges/STATUS.md).

## Layout

```
ctfbench/            # the harness (models, registry, sandbox, agent, runner, cli)
challenges/<year>/   # the dataset, one directory per challenge
docker/solver/       # the agent's sandbox image
docs/AUTHORING.md    # how to add a challenge
tests/               # pytest suite (runs without Docker or API keys)
```
